# 实验记录 (experiments_log)

`experiments/` 整个目录在 `.gitignore` 里（单个 `.h5` 权重 750 MB，不该进 git）。
但 `run.json`（超参 + 划分 + 最终指标）和 `history.csv`（逐 epoch 曲线）都很小，
值得跟代码一起进版本控制 —— 权重丢了还能重训，实验记录丢了就没法复现对比表了。

约定：每次值得留档的训练，在这里建一个和 `--run-name` 同名的子目录，
只放 `run.json` + `history.csv`。

## ⛔ 有效性分界：`lr_fix_only` 之前的四轮是**错误性实验**

前四轮（`baseline_es20` / `dcd_w3` / `dcd_l2` / `rep05_void`）跑在一个
**本项目训练脚本自己的配置错误**下：`ReduceLROnPlateau(patience=40)` 大于
`EarlyStopping(patience=20)`，学习率衰减**从未触发过**。恒定学习率下验证曲线
在平台上来回弹，而指标取"全程最优的一轮"——那本质是在随机游走上取最小值，
末 30 轮 std 约 **0.25mm**，而它们彼此的差异只有 0.13mm 量级。

**后果：这四轮之间的任何比较都不可读，它们与后续各轮之间的差值也不可归因。**

- ❌ 不得作为论文中的基线或对照
- ❌ `dcd_weight` / `dcd_lambda` 的调参结论建立在其上，一并作废
- ✅ **方法层面的一切比较，基线用 `lr_fix_only`（6.317mm），不是 `baseline_es20`**
- ✅ 完整的 DCD 2×2（`lr_fix_only` / `rep_w05` / `cd_only` / `cd_rep05_full`）
  四格**全部在修复之后**，不受影响，是干净的

⚠️ 这个错误是**本项目训练脚本引入的**，与原实现无关——原项目的训练 demo
只有 `ReduceLROnPlateau(patience=5)`，根本没有 `EarlyStopping`，不存在此冲突。
**因此它不是研究发现，不写入论文**；留在这里只为标明哪些数据不可用。

「架构」列记录的是**网络拓扑**，不是超参。它单独成列，是因为 `load_weights`
在这一维度上不设防：改动解码器 key 的来源不会改变任何一个权重的**形状**
（变的是 key 的序列长度），所以旧 checkpoint 会被静默读进新拓扑、不报错，
并给出一份属于「从未训练过的网络」的指标。`msn_skullfix.py` 开头记录的
`MSN_weights3.h5` 事故是同一失效模式的另一个入口。

目前 `arch_key` 由三个字段构成：`config` / `per_point_attn` / `use_text`。
判据是「改了它会换一套拓扑」，而不是「它是不是超参」。`use_text` 在列表里，
是因为文本分支是常数（单类别），它唯一的作用是给 D1 的 K/V 补一个偏置——
换句话说它改的是网络本身，不是训练方式。

**跨架构对比本身是成立的** —— 只要每套架构各自从头训练、拿自己的权重评估。
不成立的只有「拿旧权重灌进新拓扑」，那不是对比，是 bug。`report.eval_runs`
现在按 `Run.arch_key` 分组建模型，混着评会打印出架构清单而不是悄悄合并。

⚠️ **噪声底线随学习率衰减是否生效而变，差两个数量级 —— 读任何差异前先确认属于哪一档。**

| | LR 衰减 | 末 30 轮 CD_t 的 std | 同配置重复的 CD_t 差异 |
|---|---:|---:|---:|
| 前四轮（baseline / dcd_w3 / dcd_l2 / rep05_void） | **0 次** | ~0.25mm | — |
| 修复之后（lr_fix 起） | 6~9 次 | **~0.003~0.010mm** | **0.004mm** |

恒定学习率下验证曲线在平台上来回弹，而指标取「全程最优的一轮」——
那本质是在随机游走上取最小值。**先前采信的「运行间方差 0.49mm」是这个伪影，
不是方法的固有噪声**（详见 devlog 2026-08-07）。

所以：`baseline → dcd_l2` 那 0.13mm **不是"按噪声处理"，是整档作废**（见文首的
有效性分界）；`rep_w05 → cd_rep05_full` 那 0.05mm **是可分辨的**，因为两者都在
修复之后，且同配置重复实测只差 0.004mm。

密度这条结论**用修复后的两轮陈述**，不要跨越分界线：`cd_only` 13.60% →
`cd_rep05_full` 1.34%（两者都在修复之后，唯一差异是 repulsion）。
先前写的"12.85% → 1.34%"跨了 `baseline_es20`，含有配置错误的影响，已弃用。

对应代码状态见 git tag：`baseline-7.08mm`、`rep-6.33mm`。

`surface_quality.csv` 存的是密度/表面偏差指标（8 颗验证颅骨均值），
和上表的 CD_t 是两套互补的指标。原本由 `notebooks/MSN_surface_quality.ipynb` 产出，
2026-08-24 扩到 9 行（口径不变：`ids` 顺序里前 8 颗验证颅骨、`mesh_viz.surface_stats`；
重算的 `lr_fix` / `rep_w05` 与旧文件逐位相同，已核对）。

## 复现说明

`run.json` 里存了 `seed` / `train_ids` / `val_ids`。只要 seed 和 `--val-frac`
不变，**数据划分与权重初始化是可复现的** —— 后续改动请沿用同一组验证颅骨，
否则指标不可比。

⚠️ **但训练过程本身不可复现。** 代码没有开
`tf.config.experimental.enable_op_determinism()`，TensorFlow 在 GPU 上默认不保证
确定性（规约用原子操作、cuDNN 会自动挑算法）。实测同 seed 同配置的两轮从第 1 个
epoch 就分岔。所以 `"seed": 42` 只固定划分与初始化，**不代表结果逐位可复现** ——
实际的重复性见上表（修好学习率衰减后 CD_t 重复差异约 0.004mm）。
