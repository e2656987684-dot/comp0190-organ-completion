## ⛔ 有效性分界：`lr_fix_only` 之前的四轮是**错误性实验**

前四轮（`baseline_es20` / `dcd_w3` / `dcd_l2` / `rep05_void`）跑在一个
**本项目训练脚本自己的配置错误**下：`ReduceLROnPlateau(patience=40)` 大于
`EarlyStopping(patience=20)`，学习率衰减**从未触发过**。恒定学习率下验证曲线
在平台上来回弹，而指标取"全程最优的一轮"——那本质是在随机游走上取最小值，
末 30 轮 std 约 **0.25mm**，而它们彼此的差异只有 0.13mm 量级。

**后果：这四轮之间的任何比较都不可读，它们与后续各轮之间的差值也不可归因。**

- ❌ 不得作为论文中的基线或对照
- ❌ `dcd_weight` / `dcd_lambda` 的调参结论建立在其上，一并作废
- ✅ **方法层面的一切比较，基线用 `lr_fix_only`（6.317mm），不是 `baseline_es20`**
- ✅ 完整的 DCD 2×2（`lr_fix_only` / `rep_w05` / `cd_only` / `cd_rep05_full`）
  四格**全部在修复之后**，不受影响，是干净的

⚠️ 这个错误是**本项目训练脚本引入的**，与原实现无关——原项目的训练 demo
只有 `ReduceLROnPlateau(patience=5)`，根本没有 `EarlyStopping`，不存在此冲突。
**因此它不是研究发现，不写入论文**；留在这里只为标明哪些数据不可用。

「架构」列记录的是**网络拓扑**，不是超参。它单独成列，是因为 `load_weights`
在这一维度上不设防：改动解码器 key 的来源不会改变任何一个权重的**形状**
（变的是 key 的序列长度），所以旧 checkpoint 会被静默读进新拓扑、不报错，
并给出一份属于「从未训练过的网络」的指标。`msn_skullfix.py` 开头记录的
`MSN_weights3.h5` 事故是同一失效模式的另一个入口。

目前 `arch_key` 由四个字段构成：`config` / `per_point_attn` / `use_text` / `tie_qk_init`。
（最后一个其实是过度保守：初始化不改拓扑，tie 的权重能正常加载进不 tie 的模型。
代价只是评估时多建一个模型，无害。）
判据是「改了它会换一套拓扑」，而不是「它是不是超参」。`use_text` 在列表里，
是因为文本分支是常数（单类别），它唯一的作用是给 D1 的 K/V 补一个偏置——
换句话说它改的是网络本身，不是训练方式。

**跨架构对比本身是成立的** —— 只要每套架构各自从头训练、拿自己的权重评估。
不成立的只有「拿旧权重灌进新拓扑」，那不是对比，是 bug。`report.eval_runs`
现在按 `Run.arch_key` 分组建模型，混着评会打印出架构清单而不是悄悄合并。

| 重复对 | CD_t | 缺损覆盖 | 轮数 | 末段还在降吗 |
|---|---:|---:|---|---|

| `notext` vs `notext_r2` | 0.0013 | 0.0037 | 380 / 227 | 已走平 |

**三对里两对极紧，`tie_qk` 是例外。** 关键证据：`notext` 那对**轮数差了 153 轮**却复现到
0.0013mm —— 所以**「轮数差得多」本身不导致大方差**。分水岭是**曲线有没有走平**：

```
tie_qk    @227 6.267 -> 411 轮 6.198    多降 0.069   <- 对照停下时它还在改善
notext    @227 6.243 -> 380 轮 6.225    只降 0.018   <- 基本走平
```

**判据**：同配置重跑的差异**通常 ≲0.005mm**；当一个 run 在另一个停下的位置上**仍在下降**时
可达 0.15mm。**读小差异之前，先看 `report.epoch_matched` 的末几列有没有走平** ——
`@222 → @300` 还在明显下行的 run，其「全程最优」不能直接拿去比。
（`clump_%` 另算：三对都在 0.006~0.23pp，所以 **0.2pp 以下的扎堆差异不可信**。）

⚠️ 一个此前没注意的细节：**early stopping 盯的是 `val_loss`，而结论读的是 `val_cd_t` / 缺损覆盖。**
`lr_fix_only` 按 val_loss 在 279 轮停，但 val_cd_t 一直改善到第 277 轮 ——
**「按停止准则收敛了」≠「按报告指标收敛了」**。k 折时要给足 `--epochs`，
别让任何一格在下行段被截断（`cd_only` 与 `lr_fix_only` 都属于这一档）。

⚠️ 一个必须分清的点：**逐颅骨配对检验能证明「两个模型不同」，不能证明「这个配置更好」** ——
同配置训练两次本身就能产生跨颅骨一致的差异。两把尺子缺一不可。

恒定学习率下验证曲线在平台上来回弹，而指标取「全程最优的一轮」——
那本质是在随机游走上取最小值。**先前采信的「运行间方差 0.49mm」是这个伪影，
不是方法的固有噪声**（详见 devlog 2026-08-07）。

所以：`baseline → dcd_l2` 那 0.13mm **不是"按噪声处理"，是整档作废**（见文首的
有效性分界）。

⚠️ **2026-08-24 更正**：此处原本写着"`rep_w05 → cd_rep05_full` 那 0.05mm 是可分辨的，
因为同配置重复实测只差 0.004mm"。**这个判断不成立**，但理由不是"噪声有 0.15mm"（三对数据
出来之后，0.004 那一档其实是常态），而是 **`rep_w05` 在它停下时按报告指标还没走平**

`cd_rep05_full` 1.34%（两者都在修复之后，唯一差异是 repulsion）。
先前写的"12.85% → 1.34%"跨了 `baseline_es20`，含有配置错误的影响，已弃用。

对应代码状态见 git tag：`baseline-7.08mm`、`rep-6.33mm`。

## 采样地板（2026-08-25 实测）

`sampling_floor.csv` —— 由 `src/eval/sampling_floor.py` 产出，**100 颗完整颅骨全跑**。
**没有模型参与**：同一张网格独立采样两次，各自 FPS 到 6144 点，互相评分。
**任何模型都低不过这个数。**

| | 均值 ± std | 范围 |
|---|---|---|
| CD_t 地板 | **4.619 ± 0.252** mm | 4.061 ~ 5.238 |
| HD95 地板 | **3.974 ± 0.214** mm | 3.502 ~ 4.451 |
| 单向地板 | **2.310 ± 0.126** mm | 2.031 ~ 2.616 |

⚠️ **旧记的 4.43 / 3.79 作废** —— 那是一个未入库的临时脚本的产物。100 颗的标准误是
0.025mm，而差距 0.19mm 是 **7.5 个标准误**，所以不是抽样差异，是方法不同（旧脚本已丢）。
方向是**地板更高 → 模型自身的贡献比原以为的更小**。

### 这个数把两件事重新框定了

```
本工作  CD_t  6.355  =  地板 4.619  +  高出地板 1.736     地板占 73%
基线    CD_t 10.715  =  地板 4.619  +  高出地板 6.096     地板占 43%
缺损覆盖      3.236  =  单向地板 2.310  +  0.926          只剩 0.93mm 空间
```

⚠️ **上面的减法是粗略记账，不是严格分解** —— 两种误差不线性相加。所以"高出地板之比
3.5×"只能当**指示**。但它与**独立测得**的缺损区覆盖比（3.17×）方向一致，
两条路都指向"真实差距约 3 倍多，而不是直接比 CD_t 的 1.69 倍"。

⚠️ 4.619 还是**理想分布**的下界：真实预测有扎堆（1.34%、间距 CV 0.25 vs GT 0.145），
分布不如 FPS 均匀，实际连它都够不到。所以"高出地板的 1.74mm"里**还掺着密度的代价**
—— 这也解释了 repulsion 为什么会顺带改善 CD_t。

⚠️ **k 折之后不需要重跑**：它只依赖数据和点数，与划分、权重无关。这正是它默认跑
**全部 100 颗**而不是某一折 20 颗的原因。若确实想要"某一折自己的地板"，
CSV 是**逐颅骨一行**的，按那折的 `val_ids` 过滤取平均即可，不用重算。

## 注意力坍缩（2026-08-26 正式测量）

`attention_collapse.csv` —— 由 `src/eval/attention_collapse.py` 产出，
3 个 run × **16 块** × 3 颅骨（083 053 070）。**合并写**，按 `run`+`block`。
⚠️ **k 折之后每个最终模型各跑一次**（坍缩是一组权重的性质，与划分无关，但论文引哪份就从哪份读）。

### ⭐ 「均匀」有两种，混着说会把唯一有内容的那半抹掉

| | 判据 | 是什么 | 论文里算什么 |
|---|---|---|---|
| **STRUCTURAL** | `key_row_range` **恰好 = 0** | key 各行逐位相同（`m1 = tile(全局向量)`），softmax 必然返回 1/n | **架构事实，不是发现**。这个块不可能注意 |
| **learned collapse** | keys 有区分度但 `eff_frac` ≈ 1 | Q/K 没长出对比度 | ⭐ **「80 颗颅骨学不出 key 选择性」的证据** |

| run | uniform | 拆分 | attend |
|---|---|---|---|
| `cd_rep05_full` | **12/16** | 4 structural（D1-STA1~4）+ 8 collapsed（E-SA1~8） | 4（D2） |
| `tie_qk` | **12/16** | 同上 | 4 |
| `pp_attn` | **12/16** | **0 structural + 12 collapsed** | 4 |

⭐ `pp_attn` 演示了这个区别：D1 拿到 2048 个逐点 key 后，`key_row_range` 由 0 变成 1.47，
**从 structural 变成 learned collapse**。所以「注意力从未启动」在 `pp_attn` 上是实测结论，
在默认架构上只是结构事实。

### 编码器八块：keys 不同，注意力却完全均匀

`cd_rep05_full` 的 `eff_frac` 全 **1.000000**，而 `key_row_range` 是 **0.025~0.038**
（keys 明明有区分度）。`energy_std` 7.8e-05 ~ 2.8e-04。

`tie_qk` 的 `energy_std` 大 **5.1~12.3 倍**（沿栈递增：E-SA1~4 约 5~6×，E-SA5~8 约 8.6~12.3×），
绝对值仍 1e-3 量级，`eff_frac` 照样 0.999999 —— **绑定不解除坍缩**。

⭐ **控制列**：把同一批分数换成教科书的 `softmax(q·k/√d, axis=keys)` 重算，
所有坍缩块 `ctrl_eff_frac` ≥ **0.99999988** —— 「softmax 轴选错了」这个反驳被堵死，
且每次运行自动跑。

### D2 四块（唯一真在注意的）

| `eff_frac` | STA1 | STA2 | STA3 | STA4 |
|---|---:|---:|---:|---:|
| `cd_rep05_full` | 0.922 | 0.729 | 0.537 | 0.514 |
| `tie_qk` | 0.838 | **0.115** | **0.151** | 0.199 |
| `pp_attn` | 0.959 | 0.876 | 0.663 | 0.558 |

### ⭐ `tie_qk` 把 D2 两个块的 92% query 饿死了

`_offset_attention` 沿 **query 轴** softmax、再沿 key 轴 L1 归一化，**带一个 epsilon**
（`t / (1e-9 + reduce_sum(t, axis=2))`，逐字来自原实现，见 `msn_demo_arch.py:126,150`）。
一个在所有 key 上都输掉 query 轴竞争的 query，行和 `S_q` 落到 1e-10 量级，
**此时那个 1e-9 是分母的主要成分**，该行被压掉一个数量级。

| `tie_qk` | `row_mass` | `frac_starved` | `peak_x_unif` |
|---|---:|---:|---:|
| D2-STA1 | 1.000 | 0% | 2.0 |
| **D2-STA2** | **0.079** | **92.4%** | 665.6 |
| **D2-STA3** | **0.079** | **92.2%** | 302.4 |
| D2-STA4 | 0.982 | 27.4% | 411.5 |

**全表只有 `tie_qk` 出现**（`cd_rep05_full` / `pp_attn` 每块都是 0%），跨 3 颅骨极稳。

⚠️ **两件事同时发生，措辞要分清**：`tie_qk` 的 D2 `peak_x_unif` 是 302~666（对照 2.8~79），
注意力**确实也真的更尖**；饿死与尖锐是同一现象的两面（沿 query 轴集中 ⇒ 多数行没质量）。

⭐ 这给 `tie_qk` 的否决多了一条机制：它不只是「无可复现精度效应 + 密度变差」，
还把 D2 两个块推进了一个**退化的归一化状态**。

## 表面粗糙度：GT vs 预测（2026-08-26 正式测量）

`roughness.csv` —— 由 `src/eval/roughness.py` 产出，`cd_rep05_full` × 8 颗验证颅骨
（与 `surface_quality.csv` 同一批）× 5 个邻域尺度。**合并写**，按 `run`+`id`+`k`。

**它支撑的是一个否定性决策**：导师提议加表面平滑惩罚项，而 2026-08-05 的测量说没有可捡的便宜，
于是整个表面质量方向转去做**密度**（→ repulsion，全项目最硬的结论）。那个测量的脚本没入库。

### 结论：两者在统计上**无法区分**，平滑惩罚项没有靶子

| k=16（原始论断的口径） | GT | 预测 | Δ |
|---|---:|---:|---:|
| `rough_norm`（残差 / 点间距） | 0.512 | 0.496 | **−0.016** |

⚠️ **但这个 Δ 不显著**：逐颅骨 std 0.029、配对 SE 0.010、**Wilcoxon p = 0.195、3/8 颗方向相反**。
按本项目的判决清单（p<0.002 或多数颅骨一致）**远不过线**。

> **正确的表述是「测不出差别」，不是「预测更平滑」，更不是旧记的「预测更粗糙」。**
> n=8 的检出下限约 Δ≈0.03（GT 值的 6%），所以只能说：**若真有差距，也在 6% 以内、方向未知。**
> 平滑惩罚项**没有可优化的目标** —— 原决策成立，且理由比原来硬。

⚠️ **旧数字的符号是反的**：devlog 2026-08-05 记的是 GT 0.736 / pred 0.760（Δ **+0.024**，
预测更粗糙）。绝对值对不上是定义不同（旧脚本已丢），但**方向也反了**。
⭐ **这是第三个被正式化的临时脚本数字，也是第三个被发现有错的**
（前两个：采样地板 4.43→4.619、注意力坍缩的 D2 读数）。**三个全中。**

### 为什么这个度量不能再往下做（k 扫描，同样此前只在 devlog）

`spread_mm` = 邻域沿法向的展开，即"这个邻域自己有多厚"：

| k | 8 | 16 | 24 | 48 | 128 |
|---|---:|---:|---:|---:|---:|
| GT `spread_mm` | 5.44 | 7.87 | 8.72 | 10.25 | **14.17** |

骨壳厚 5~7mm。若污染只来自厚度，这一列该在 6mm 附近**走平**；实测一路爬到 14.17mm，
**说明大 k 处污染换成了颅骨自身的曲率**。⭐ **没有哪个 k 是干净的，换尺度不是解法** ——
`local_roughness` 的 docstring 里有合成数据的演示：一个**完全平整**的表面，
仅因存在 6mm 的第二层，粗糙度就从 0.00mm 被抬到 1.56mm。

⭐ 一个顺带的观察（不构成结论）：**k=128 时预测在 8/8 颗颅骨上都比 GT 平滑**（Δ −0.108）。
方向与 devlog 2026-08-05 的一个旧猜测一致 —— GT 来自二值体素的 marching cubes、带阶梯伪影，
模型不复现它。⚠️ 但 k=128 正是曲率污染最重的一档，**不要拿它下结论**。

## 法向可估性 —— Poisson 的闸门（2026-08-27 实测，⛔ 不通过）

`normal_quality.csv` —— 由 `src/eval/normal_quality.py` 产出，8 颗验证颅骨的 **GT 点** × 4 个 k。
**全程无模型参与**，真值取自网格面法向（k 折后不用重跑）。

**它回答的是 TODO 9 的前置问题**：Poisson 要的不是点，是**带朝向的法向**，而法向只能从点云自己估。

### 结论：⛔ 任何一档 k 都不可用

| k | 邻域半径 | 邻居在对面片 | 平面就错了 >20° | **定向后翻转** |
|---:|---:|---:|---:|---:|
| 6 | 6.38mm | 22.3% | 77.9% | **53.3%** |
| 8 | 7.25mm | 26.8% | 76.8% | **49.5%** |
| 12 | 8.57mm | 32.9% | 74.4% | **51.5%** |
| 16 | 9.65mm | 36.3% | 71.7% | **51.9%** |

**翻转 ≈ 50% 是抛硬币** —— 不是"朝向估得不准"，是**没有朝向信息**。Poisson 的原理就是从法向场
解指示函数，喂一个一半朝里一半朝外的场，出来的不是差一点的面。

四条佐证：

1. **不是离群颅骨带的**：8 颗逐一看，k=8 翻转 0.454~0.547、std 0.036。
   **最好的一颗、在最好的 k 上，仍有 45.4% 翻转。**
2. **不是图断了**：`mst_visited` 全部 = 6144，最小生成树连通了每个点。
3. ⭐ **合成对照几乎精确预言了实测**：合成双层壳（6mm 壳/3.0mm 间距）平面错 79.1%、翻转 50.1%；
   实测（k=8）76.8% / 49.5%。同一份代码在**单层球面**上是 0.8° / 0% 翻转 ——
   **估计器是对的，是几何把它打垮的**。
4. **没有更小的 k 可逃**：k=6 时邻域半径已是 **6.38mm**，而骨壳厚 5~7mm ——
   **最小的可用邻域就已横跨整个骨壳**。退路是被测量堵死的，不是被假设堵死的。

⚠️ **k 越大「方向」略好而「朝向」纹丝不动**（平面错 77.9%→71.7%，翻转 53.3%→51.9%）。
内外两层大致平行，一起拟合得到一个"板"，板的最小方差轴 ≈ 共同法向**轴**，所以 k 大轴更稳；
**但轴不带符号**，而符号正是被两层的对立真值毁掉的。**Poisson 两样都要，垮得最彻底的是它更需要的那样。**

### 准确的结论（论文口径）

> ❌ 不是"Poisson 这个算法不行"
> ✅ 是 **"6144 个点、约 4mm 间距的点云，在 5~7mm 厚的骨壳上无法恢复表面朝向，
> 因此基于法向的表面重建不可用"** —— 这是关于**输出表示**的结论。

⚠️ **在 GT 点上测的**，而 GT 是 FPS 采样、零扎堆，是**最乐观**的情形；
预测点有 1.34% 扎堆，只会更差。**对预测更加成立。**

⚠️ 没被排除的：更密的点云、法向来自别处（如另训法向预测器）、不需要法向的重建方法
（项目里的距离场重建属此类，但它自己的地板实测中位 5.3mm，离目标更远）。

### 顺带：`prepare_skullfix.py` 已验证逐位可复现

为取得真值法向，脚本重跑了整条数据管线并强制核对：**8 颗全部 `GT 点最大差 0.00e+00`**，
`scale` 差 ~2e-06（float32 存储精度）。这以前从未验证过。
⭐ 意义：`/root` 是临时盘，**万一 `data/cache/*.npz` 丢了，缓存能重建成完全相同的一份**，

### 基线 vs 本工作（2026-08-25，基线取 5 次抽样均值，同一批 20 颗）

| 指标 | 预训练基线 | 本工作 `cd_rep05_full` | 倍数 |
|---|---:|---:|---:|
| CD_t（全点云） | 10.715 | 6.355 | 1.69× |
| **缺损覆盖（主指标）** | **10.264** | **3.236** | **3.17×** |
| 缺损精度 | 3.100 | 2.913 | 1.06× |
| **洞里放的点数** | **174** | 492 | 0.35× |
| 缺损 F1@0.05 | 0.295 | 0.965 | 0.31× |

⭐ **两条方法学结论：**

1. **全点云指标严重低估差距**（1.69× vs 缺损区 3.17×）。这是「以缺损区覆盖为主指标」
   最强的证据，而且是在一个**外部模型**上验证的，不是自家配置之间的比较。
2. **缺损精度那 1.06× 是假象** —— 基线只往洞里放了 174 个点（GT 约 395），

## 复现说明

`run.json` 里存了 `seed` / `train_ids` / `val_ids`。只要 seed 和 `--val-frac`
不变，**数据划分与权重初始化是可复现的** —— 后续改动请沿用同一组验证颅骨，
否则指标不可比。

⚠️ **但训练过程本身不可复现。** 代码没有开
`tf.config.experimental.enable_op_determinism()`，TensorFlow 在 GPU 上默认不保证
确定性（规约用原子操作、cuDNN 会自动挑算法）。实测同 seed 同配置的两轮从第 1 个
epoch 就分岔。所以 `"seed": 42` 只固定划分与初始化，**不代表结果逐位可复现** ——
实际的重复性见上表（修好学习率衰减后 CD_t 重复差异约 0.004mm）。
